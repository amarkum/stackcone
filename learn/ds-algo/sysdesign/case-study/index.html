Design a URL shortener: a user pastes a long URL and gets back something like https://short.ly/3ORDSU. Opening that link redirects to the original. This is the first full product in the course — it uses IDs, hashing, caching, a read-heavy path, and async analytics.

Step 1 — Clarify

Questions worth asking before you draw boxes:

  • Custom aliases (/my-launch) and expiry dates?
  • User accounts, or anonymous create?
  • Click analytics — count only, or country/referrer/time series?
  • Redirect SLA (p99)? Read/write ratio?
  • Must codes be unguessable? Allowed character set?

v1 we will build: create, redirect, optional custom alias and expiry, click counts. Out of scope unless asked: QR codes, A/B links, a full BI product. Non-functional: redirect p99 under 50–100 ms, high availability, ~100:1 reads to writes, codes not sequential, we will pick 301 vs 302 on purpose.

Step 2 — Back-of-the-envelope

new_urls_per_month = 100_000_000
writes_per_sec = (new_urls_per_month / 30) / 86_400     # ~40/s
reads_per_sec = writes_per_sec * 100                    # ~4,000/s average
peak_reads = reads_per_sec * 3                          # ~12,000/s

records_5y = new_urls_per_month * 12 * 5                # 6 billion
bytes_per_row = 500
storage_tb = records_5y * bytes_per_row / 1e12
cache_hot = 0.20 * reads_per_sec * 200                  # 20% of QPS, 200 B values
print(round(writes_per_sec), round(reads_per_sec), round(peak_reads), round(storage_tb, 1))
Output
39 3858 11574 3.0

Forty writes/s is easy. Four thousand average redirects (12k peak) is still modest if most hit a cache. Three terabytes in five years fits one database cluster. You do not open with sharding; you open with Redis in front of a primary + replicas. If the interviewer 10xes traffic, then hash-shard by code.

Code space: 62^7 ≈ 3.5 trillion seven-character base62 strings, far above 6 billion rows. Six characters (56 billion) is also enough if you are willing to handle collisions.

Step 3 — API

POST /api/v1/urls
  { "long_url": "https://example.com/a/very/long/path",
    "custom_alias": "launch",          // optional
    "expires_at": "2027-01-01T00:00:00Z" }
  -> 201 { "short_url": "https://short.ly/launch", "code": "launch" }
  400 invalid URL / reserved word
  409 alias taken

GET  /{code}  -> 302 Location: <long_url>
               -> 404 if missing or expired

GET  /api/v1/urls/{code}  -> metadata + click summary  (authz)

DELETE /api/v1/urls/{code}  -> 204

Version the API. Creating is authenticated or rate-limited. Redirect is public and must stay tiny — no joins, no analytics write on the request thread.

Step 4 — Data model

urls (
  code        VARCHAR(16) PRIMARY KEY,   -- base62 or alias
  long_url    TEXT NOT NULL,
  created_at  TIMESTAMPTZ NOT NULL,
  expires_at  TIMESTAMPTZ NULL,
  user_id     BIGINT NULL,
  is_custom   BOOLEAN NOT NULL DEFAULT FALSE
)
-- unique(long_url) only if you want one code per URL; usually you do not

-- NOT updated on redirect:
-- clicks live in an events log / rollup tables, not on this row

Access is always by primary key code. That is why a relational DB or a KV store both work. Do not store click counters on this row if you care about redirect latency — every increment would contend on the hot keys.

Step 5 — High-level design

flowchart TB subgraph write [Create] C[Client] --> LB[Load balancer] LB --> APP[App servers] APP --> ID[ID / code service] APP --> DB[(urls table)] end subgraph read [Redirect] B[Browser] --> LB2[Load balancer] LB2 --> APP2[App servers] APP2 --> Redis[(Redis cache)] Redis -->|miss| DB APP2 -->|click event| Q[(Queue)] Q --> Agg[Analytics workers] end

Writes allocate a code and insert. Redirects hit Redis first. Clicks are fire-and-forget onto a queue so the 302 never waits on analytics.

Write path

  1. Validate the URL (scheme, length, block-list of malware domains).
  2. If custom alias: reject reserved words (api, health, admin), check uniqueness, insert.
  3. Else allocate a code (next section), insert, return the short URL.
  4. Optionally seed Redis so the first redirect is a hit.

Read path

  1. Lookup code in Redis. On hit, check expires_at, 302.
  2. On miss, read DB, fill cache with a long TTL (hours to a day), 302.
  3. Publish {code, ts, country, referrer, ua} to the queue after the response is on the wire (or at least without waiting for the consumer).

Step 6 — Generating the short code

Seven base62 characters give 62^7 ≈ 3.5 trillion codes.

  • Hash the long URL (SHA-256, take 42 bits, encode). Deterministic: the same URL always shortens the same way. Collisions: retry with a salt. You cannot have two codes for one URL, which some products want.
  • Counter + base62: encode a Snowflake or ticket id. No collisions. Sequential codes are guessable — permute bits or keep this as an internal id only.
  • Random 7 chars + unique index, retry on conflict. Simple, unguessable, slightly more inserts. This is a strong default for a public shortener.
ALPHABET = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ"

def base62(n: int) -> str:
    if n == 0:
        return ALPHABET[0]
    out = []
    while n:
        n, r = divmod(n, 62)
        out.append(ALPHABET[r])
    return "".join(reversed(out))

print(base62(125), base62(3_500_000_000), 62 ** 7)
Output
21 3ORDSU 3521614606208

Step 7 — Deep dives

301 vs 302

301 (permanent) lets browsers and CDNs cache the hop — cheaper, but later clicks never reach you. 302 (or 307) keeps every click visible. Most shorteners use 302 because analytics is the product. Say this out loud.

Cache

Cache-aside Redis keyed by code, value = JSON of long URL + expiry. TTL of hours plus LRU. Hottest links (spam campaigns, news) never touch the DB. On delete or expiry, DEL the key. Add jitter to TTLs so a popular key does not stampede the DB when it expires.

Analytics

The redirect path must not UPDATE urls SET clicks = clicks + 1. Enqueue events; workers batch-write to a column store or daily rollup tables (code, day, country, count). Dashboards read rollups. If the queue is down, drop or buffer events — never fail the 302.

Abuse

Rate-limit creates per IP and per account (lesson 7). Scan destinations against a malware list asynchronously and disable bad codes. Captcha for anonymous users. Custom aliases need a reserved-word list.

Expiry and multi-region

Check expires_at on every read; a sweeper deletes old rows. Global: replicate the KV / DB, DNS failover. A brand-new link may 404 in the other region for a second — acceptable if you say it. For stricter create-then-immediately-open, read-your-writes from the primary or replicate the new key to Redis in both regions.

Structure beats a clever hash

Walk clarify → numbers → API → schema → diagram → code generation → 301/302 and analytics. Invite them to pick the deep dive.
