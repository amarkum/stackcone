Migrate Cursor Chat to Claude Code

June 2026 · Published by Amar Kumar

Moving from Cursor Composer to Claude Code does not carry your threads over. Cursor keeps chats in state.vscdb; Claude Code reads CLAUDE.md, terminal sessions, and project memory. The gap is manual — but straightforward if you treat migration as knowledge transfer, not session replay.

Workflow overview

state.vscdb  →  cursor_export.py  →  JSON + Markdown
                                         ↓
                    Curate P0/P1 threads  →  context-pack/
                                         ↓
                    CLAUDE.md + preamble  →  claude (terminal)

Step 1 — Export and triage

python3 cursor_export.py --out ./cursor-export
python3 cursor_export.py --list   # pick composer IDs

Tag each thread:

  • P0 — active feature or bug you are still shipping
  • P1 — architecture, conventions, or infra worth keeping
  • P2 — archive only (search if needed later)

Do not paste 100+ full threads into Claude — context limits and noise will hurt you.

Step 2 — Build a context pack

Create a folder (add to .gitignore if it contains client names):

context-pack/
  CLAUDE-bootstrap.md
  threads/
    auth-refactor.md
    rag-pipeline.md
  plans/
    api-redesign.plan.md

Thread file template

# Thread: Auth refactor
composerId: abc-123-def
Exported: 2026-06-19

## Summary
- JWT + refresh rotation (no cookie sessions)
- Deprecate `sessions` table in migration 20260619

## Transcript
### User
We need to migrate off cookie sessions...

### Assistant
Recommend refresh tokens with rotation...

Strip linter dumps, failed tool retries, and duplicate drafts. Keep decisions, file paths, and snippets that still compile.

Distill CLAUDE-bootstrap.md

One file Claude Code should treat as ground truth:

  • Stack versions (Node, Python, DB)
  • Test / lint / deploy commands
  • Non-obvious repo conventions
  • Open TODOs with paths
  • Pointers to threads/*.md for deep history

Step 3 — Seed Claude Code

  1. Merge into CLAUDE.md — copy bootstrap content into your repo root (or merge with existing instructions).
  2. Start a session in the project: 
    cd my-app && claude
  3. First message (example): 
    I migrated from Cursor. CLAUDE.md has current conventions.
For auth background see context-pack/threads/auth-refactor.md.
Continue from the open TODOs listed there.
  4. Project memory — store stable facts (package manager, CI entrypoint). Never store API keys.
  5. Large threads — import summary + last ~10 messages, not 200k tokens of tool noise.

Step 4 — Ongoing hygiene

  • When a Cursor thread resolves, merge the decision into CLAUDE.md and delete the thread file.
  • Re-export monthly if you still use both tools.
  • One canonical CLAUDE.md — avoid duplicating rules across files.
  • Keep context-pack/ out of git if it has private URLs or customer names.

FAQ

Will Claude Code read my Cursor composerId?

No — IDs are for your filenames and traceability only.

Should I automate context-pack generation?

Yes — extend cursor_export.py to filter bubbles, emit summaries, and copy plans in one pass.

What about Cursor Plan mode vs Claude planning?

Both output markdown. Copy the plan file, then re-run planning in Claude Code against your current tree.
